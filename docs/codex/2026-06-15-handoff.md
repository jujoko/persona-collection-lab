## 1. 프로젝트 목적

LLM 기반 페르소나 연구를 위한 게임형 데이터 수집 프로토타입.

**핵심 문제**: 기존 LLM 페르소나 연구는 사전에 정의된 성격 축(Big Five 등)에 페르소나를 맵핑하는 방식에 의존하는데, 이 축 자체가 LLM의 학습 데이터에 포함되어 있어 실제 행동 다양성과는 분리된 허구적 일관성이 나타남.

**접근**: 캐릭터를 도덕적 딜레마 사건에 반복 노출시키고 실제 행동 선택 데이터를 수집 → 행동 기반 latent persona 공간 학습.

**GitHub**: https://github.com/jujoko/persona-collection-lab

## 2. 현재 버전 (v0.2.3) — 무엇이 구현되어 있는가

### 게임 흐름

```
유저 텍스트 프롬프트 (캐릭터 설명)
  → all-MiniLM-L6-v2 (Node.js, port 8787) → 384차원 임베딩
  → M1 adapter (MLP 384→64→8) → 8차원 latent seed
  → 성장 사건 G001~G004 (유아기→청년기, 현대 한국 단서어) → latent 변화 누적
  → 성인기 사건 ME001~ME005 (현대 도덕 딜레마) → 행동 선택 → 결과
  → 엔딩 10종 결정
  → 유저 피드백 → gradient update → 재시뮬레이션 비교
  → Supabase 저장
```

### 세 가지 모델

| 모델 | 역할 | 파일 | 현재 상태 |
|---|---|---|---|
| **M1** | 프롬프트 → 8차원 latent seed | `ml/m1_adapter.pt` | ✅ 학습 완료, 서버 연동 완료 |
| **M2** | 페르소나 × 사건 → 행동 결정 | `ml/train_m2.py` (가중치 없음) | 🔶 rule-based cosine similarity로 대체 운영 중 |
| **M3** | latent schema 구조 설계 | `ml/train_m3.py` (가중치 없음) | 🔶 규칙 기반 8차원 고정 |
| **Play Model** | 프롬프트 → skills/hobbies 임베딩 | `ml/play_model.pt` (학습 중) | 🔄 Phase 1 학습 진행 중 |

### 인프라

| 서버 | 역할 | 포트 |
|---|---|---|
| Node.js (`src/server.mjs`) | 메인 웹서버 + 임베딩 (`Xenova/all-MiniLM-L6-v2`) + Supabase 연동 | 8787 |
| Python (`ml/inference_server.py`) | M1 + Play Model 추론 | 8788 |

### 데이터 저장

- **Supabase Postgres** (운영): `characters` / `simulations` / `feedback` 테이블
- **localStorage** (fallback): 서버 없이 실행 시

### 콘텐츠

| 구분 | 내용 |
|---|---|
| 성장 사건 | G001~G004 (유아기→청년기, 현대 한국 키워드) |
| 성인기 사건 | ME001~ME005 (내부고발·가족의빚·자원배분·금지된방법·조직의압력) |
| 엔딩 | 10종 (survivor/whistleblower/conformist/reformer/exile/caregiver/opportunist/martyr/forgotten/changemaker) |

## 4. Play Model 구조 (가장 중요한 현재 진행 작업)

### 왜 Play Model이 필요한가

M2(행동 결정 모델)가 올바르게 작동하려면 `action_id`에 맵핑된 `action_embedding`이 필요한데, 이 임베딩을 수동으로 설계하면 검증되지 않은 신호로 학습하는 문제가 생긴다.

Play Model은 캐릭터 텍스트 → skills/hobbies 임베딩을 학습하고, 이 임베딩을 action 후보들과 cosine similarity 비교해 `action_id`를 결정한다. 이 방식은 수동 설계 없이 의미 공간에서 행동을 선택하는 구조다.

### 모델 구조

```
입력: 캐릭터 설명 텍스트 (자유 형식)
  → klue/roberta-base (768-dim) [encoder]
  → Skills Head: MLP (768→128→768) → skills_embedding
  → Hobbies Head: MLP (768→128→768) → hobbies_embedding

Stage 2 (학습 없음):
  skills_embedding + hobbies_embedding
  → cosine similarity vs. action 후보 klue/roberta-base 임베딩
  → argmax → action_id
```

### Curriculum Learning (3단계)

| Phase | FREEZE_ENCODER | SAMPLE_SIZE | 목적 |
|---|---|---|---|
| 1 | True | 100,000 | head만 학습, 빠른 기본 fitting |
| 2 | True | 500,000 | 더 큰 데이터로 refinement |
| 3 | False | None (전체) | encoder까지 fine-tuning |

**현재 상태**: Phase 1 진행 중 (`FREEZE_ENCODER=True`, `SAMPLE_SIZE=100_000`)

### 학습 재개 방법

```bash
# Phase 1 이어서 학습 (체크포인트에서 재개)
python ml/train_play_model.py

# Phase 2로 전환 (train_play_model.py 상단 설정 변경 필요)
# FREEZE_ENCODER = True
# SAMPLE_SIZE    = 500_000
# → python ml/sample_dataset.py --size 500000 먼저 실행

# Phase 3로 전환
# FREEZE_ENCODER = False
# SAMPLE_SIZE    = None
```

체크포인트: `ml/play_model_ckpt/` 에 에폭마다 저장됨.

### 중요한 제약

- action 임베딩도 반드시 **klue/roberta-base**로 인코딩해야 함
- M1이 사용하는 MiniLM(384-dim)과 임베딩 공간이 다름 — 섞으면 안 됨

### ⑤ M3 schema discovery → M2 학습 (데이터 충분히 쌓인 후)

M3와 M2는 데이터 없이는 학습 의미가 없으므로 ④ 이후로 미룸.

**M3** (`ml/train_m3.py`):
- 수집된 캐릭터-사건-행동 데이터로 latent schema 분석
- 현재 8차원 고정 → 최적 차원 수 탐색 (8/16/32/64)
- 출력: 차원별 의미 레이블, 사건 민감도 행렬

**M2** (`ml/train_m2.py`):
- M3 결과로 action embedding 재설정 후 KV injection 학습
- 필요 인프라: frozen Qwen2.5-1.5B (로컬 또는 API)
- 합성 데이터 생성: `python ml/build_training_data.py --n-personas 500 --judge claude`

## 6. 알려진 이슈 / 설계 제약

1. **Play Model action 임베딩 공간**: MiniLM(M1)과 klue/roberta-base(Play Model) 임베딩 공간이 다름. `inference_server.py`에서 action 임베딩 인코딩 시 모델을 섞지 않도록 주의.

2. **M2 학습 보류 이유**: action embedding이 수동 설계되어 있어 검증되지 않은 신호로 학습 불가. M3 schema discovery 이후에야 올바른 action embedding을 얻을 수 있음. 지금 M2를 억지로 학습시키면 무의미한 가중치가 됨.

3. **Fly.io 메모리**: klue/roberta-base(약 500MB)와 M1 adapter를 같이 로드하면 1GB 근방. free tier(256MB)로는 OOM. 배포 전 플랜 확인 필요.

4. **Supabase 비활성 방지**: Supabase 무료 플랜은 7일 미사용 시 DB 일시 중단. 배포 후 `/api/health` ping 설정 필요.

5. **임베딩 서버 cold start**: Node.js 서버 첫 기동 시 `Xenova/all-MiniLM-L6-v2` 다운로드 (~90MB). Fly.io 볼륨에 캐시하거나 이미지에 포함해야 cold start 방지.
