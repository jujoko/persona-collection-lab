# M3 설계 및 학습 계획

## 역할

수집된 행동 데이터에서 latent persona space의 구조를 발견한다.

- 몇 차원이 적절한가
- 각 차원이 실제로 무엇을 의미하는가
- 어떤 차원이 행동 차이를 설명하는가
- 차원 간 상관관계는 어떤가

M3의 출력이 M1의 latent 공간 정의와 M2의 action embedding 재설정에 영향을 준다.

---

## 현재 상태: 규칙 기반 bootstrap

8차원 고정 schema로 운영 중. 각 차원(z0~z7)의 의미는 수동으로 정의되지 않은 상태이며, M3가 데이터에서 발견하기를 기다리고 있다.

---

## M3는 미리 설계하지 않는다

M3의 핵심 원칙: **축의 의미를 사전에 정의하지 않는다.**

"z0은 공동체 지향, z1은 불안감" 같은 사전 설계는 연구자의 편견을 latent 공간에 주입하는 것이다. M3는 실제 행동 데이터에서 어떤 패턴이 행동 차이를 설명하는지 발견해야 한다.

---

## 발견해야 할 것들

### 1. 최적 차원 수

행동 예측 loss를 기준으로 8/16/32/64차원을 비교해 최적 D를 탐색한다.

### 2. 차원별 분산

분산이 낮은 차원은 대부분의 페르소나가 비슷한 값을 가진다 → 행동 차이를 설명 못함 → 제거 후보.

### 3. 차원 간 상관

높은 상관을 가진 두 차원은 같은 정보를 중복으로 담고 있다 → 하나로 합치거나 제거.

### 4. 사건 민감도

각 차원이 어떤 사건에서 행동 변화에 영향을 미치는지 측정한다.

```
ME001(내부고발)에서 z2가 높은 페르소나가 reports_to_authorities를 더 많이 선택한다
→ z2는 ME001에서 민감한 차원
```

---

## 학습 시점

M3는 **배포 후 충분한 데이터가 쌓인 뒤** 실행한다.

필요한 데이터:
- (latent, event, action) 튜플 최소 수백 개
- 가능하면 피드백 포함

---

## 실행

```bash
python ml/train_m3.py
```

출력: `ml/learned_schema.json`

```json
{
  "optimal_dims": 8,
  "adjacency": [[1.0, 0.12, ...], ...],
  "dimension_variance": [0.82, 0.71, ...],
  "event_sensitivity": {
    "ME001": [0.3, 0.1, 0.8, ...],
    "ME002": [0.6, 0.4, 0.2, ...]
  }
}
```

---

## M3 분석 후 연쇄 효과

```
M3 schema 발견
    ↓
불필요한 차원 제거 → latent dim D 재결정
    ↓
M1 adapter 재학습 (D 변경 시)
    ↓
action embedding 데이터 기반으로 재설정
    ↓
M2 KV injection 학습 (adapter만 재학습)
```
