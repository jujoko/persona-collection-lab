# LLM 기반 페르소나 생성·시뮬레이션 연구 기획 정리

## 1. 이 문서의 목적

이 문서는 이번 세션에서 논의한 **LLM 기반 페르소나 생성 연구**의 전체 맥락을 이어가기 위한 정리본이다.  
핵심은 단순히 “성격 좋은 캐릭터 프롬프트를 만드는 법”이 아니라, **사람처럼 판단하고 행동하는 개체형 AI를 만들기 위해 필요한 페르소나 표현 방식과 데이터 수집 방법을 설계하는 것**이다.

기존의 많은 페르소나 기반 에이전트 연구는 대체로 다음 방식에 기대고 있다.

- 사람이 이해 가능한 성격 차원을 미리 정의한다.
- 직업, 성격, 말투, 배경, 목표 등을 프롬프트에 작성한다.
- LLM은 그 프롬프트를 바탕으로 특정 인물처럼 대화하거나 행동한다.
- 평가도 주로 “그 캐릭터답게 말했는가”, “설정과 일관적인가”에 집중된다.

그러나 이 방식에는 한계가 있다.  
이 축들은 연구자가 임의로 설계한 것이라, 페르소나가 부여된 LLM은 그 축의 특징만을 갖고 학습된다. 결국 LLM의 실제 판단 구조가 아니라 연구자가 사전에 정한 범주 안에 캐릭터를 밀어 넣는 방식이 된다.  
따라서 본 연구는 **사전 정의된 페르소나 축에만 의존하지 않고, 유저가 만든 캐릭터와 그 캐릭터의 행동 결과를 통해 새로운 페르소나 표현 공간을 학습할 수 있는 구조**를 지향한다.

---

## 2. 연구의 출발점

### 2.1 문제의식

현재의 페르소나 에이전트는 보통 다음과 같이 구성된다.

```text
페르소나 설명문 입력
→ LLM이 해당 인물처럼 응답
→ 응답의 캐릭터성 / 일관성 평가
```

이 방식은 구현이 쉽고 직관적이라는 장점이 있다.  
하지만 연구적으로 보면 중요한 질문이 남는다.

> “사람처럼 행동하는 페르소나는 반드시 사람이 해석 가능한 문장형 속성으로만 정의되어야 하는가?”

예를 들어, “외향성”, “성실성”, “공감성”, “위험 감수성” 같은 축은 사람이 이해하기 쉽다.  
그러나 실제 행동을 만들어내는 내적 구조는 이보다 훨씬 복잡할 수 있다.  
어떤 성격 축들은 서로 독립적이지 않고, 서로 연결되어 있으며, 특정 상황에서 함께 활성화되거나 억제될 수 있다.

따라서 본 연구에서는 페르소나를 단순한 속성 리스트가 아니라, **여러 성격 축이 서로 연결되어 있는 네트워크형 구조**로 바라본다.

---

## 3. 핵심 연구 아이디어

## 3.1 페르소나를 “고정 프롬프트”가 아니라 “행동을 만들어내는 구조”로 본다

기존 방식은 다음에 가깝다.

```text
캐릭터 설명문 = 페르소나
```

본 연구에서의 관점은 다르다.

```text
캐릭터 설명문 + 상황별 판단 + 반복된 행동 결과 = 페르소나 구조
```

즉, 페르소나는 단순히 “이 캐릭터는 용감하고 친절하다”라는 설명이 아니라,  
**위기 상황, 갈등 상황, 유혹 상황, 관계 상황에서 어떤 판단을 반복적으로 하는가**를 통해 드러나는 구조다.

---

## 3.2 성격 축은 독립된 체크리스트가 아니라 연결망이다

초기에는 페르소나를 2차원 구조로 상상했다.  
다만 여기서 말한 2차원은 단순히 x축, y축으로 성격을 배치하는 의미가 아니라,  
**각 성격 축들이 서로 연결되어 있고, 그 연결이 행동 결과에 영향을 미치는 구조**에 가깝다.

비유하면 다음과 같다.

```text
성격 축 A ── 성격 축 B
   │             │
성격 축 C ── 성격 축 D
   │             │
성격 축 E ── 성격 축 F
```

이 구조는 딥러닝의 신경망처럼 생각할 수 있다.  
각 노드는 성격·가치·동기·욕망·두려움·관계성 같은 요소이고,  
각 연결은 한 요소가 다른 요소에 미치는 영향을 의미한다.

예를 들어:

- “정의감”이 강하면 “위험 회피”를 억제할 수 있다.
- “생존 욕구”가 강하면 “도덕성”이 약화될 수 있다.
- “타인 인정 욕구”가 강하면 “권력 추구”와 결합될 수 있다.
- “불안”이 높으면 “공격성” 또는 “회피성”으로 분기될 수 있다.

따라서 핵심은 단일 축 점수가 아니라,  
**축들 간의 관계와 그 관계가 상황 속에서 어떻게 행동으로 드러나는가**이다.

## 4. 학습 가능성에 대한 정리

### 4.1 지도학습만으로는 어렵다

처음에는 다음과 같은 의문이 있었다.

> “축을 업데이트하는 것이 딥러닝이라면, 결국 정답 데이터가 필요한 것 아닌가?”

맞다.  
지도학습을 하려면 다음 형태의 데이터가 필요하다.

```text
입력: 캐릭터 설명 + 상황
정답: 해당 캐릭터가 선택할 행동 / 판단 / 결과
```

하지만 현실적으로 “이 페르소나가 이 상황에서 반드시 이렇게 행동해야 한다”는 정답을 대규모로 수집하기는 어렵다.  
특히 사람의 성격과 판단은 하나의 정답으로 고정되기 어렵다.

따라서 본 연구는 처음부터 완전한 지도학습을 목표로 하기보다,  
게임을 통해 다음 데이터를 먼저 수집하는 방향이 적절하다.

- 유저가 어떤 캐릭터를 만들었는가
- 그 캐릭터가 어떤 상황에서 어떤 행동을 했는가
- 그 행동이 어떤 결과로 이어졌는가
- 유저가 그 결과를 납득했는가
- 같은 상황에서 다른 캐릭터는 어떻게 다르게 행동했는가

이 데이터를 기반으로 이후에는 다음 방식들을 고려할 수 있다.

- 비지도학습: 유사한 캐릭터·행동 패턴을 군집화
- 자기지도학습: 캐릭터 설명으로부터 행동을 예측하거나, 행동 로그로부터 캐릭터 벡터를 복원
- 약지도학습: LLM 또는 규칙 기반 평가를 활용해 행동-페르소나 일관성 점수 생성
- 대조학습: 서로 다른 캐릭터가 같은 상황에서 다르게 행동한 사례를 학습
- 선호학습: 유저가 더 납득한 결과와 덜 납득한 결과를 비교

### 4.2 페르소나 구조는 사전 정의된 성격축이 아니라 학습되는 잠재 공간이어야 한다

중요한 수정점은 다음과 같다.  
본 연구에서 말하는 “페르소나 구조”는 연구자가 미리 정한 `위험 감수성`, `이타성`, `충성심`, `도덕성` 같은 축의 조합으로 고정되면 안 된다.

이런 축은 사람이 이해하기 쉽고 초기 설명에는 유용하지만, 그것을 모델의 실제 내부 표현으로 삼으면 기존 페르소나 연구의 한계를 반복하게 된다.  
이 축들은 연구자가 임의로 설계한 것이라, 페르소나가 부여된 LLM은 그 축의 특징만을 갖고 학습된다. 결국 사람이 이름 붙인 성격 카테고리 안에 캐릭터를 다시 밀어 넣는 방식이 된다.

따라서 구현과 연구 설계에서 구분해야 할 것은 다음이다.

```text
해석용 태그:
사람이 결과를 이해하기 위해 붙이는 보조 설명

학습용 페르소나 표현:
행동 로그와 피드백으로부터 학습되는 latent vector / latent network
```

프로토타입 단계에서도 페르소나의 본체는 다음과 같이 표현하는 것이 더 적절하다.

```json
{
  "character_id": "C001",
  "latent_persona": [0.21, -0.58, 0.44, 0.09, -0.31, 0.62, -0.12, 0.37],
  "latent_edges": [
    {
      "source": "z1",
      "target": "z5",
      "weight": 0.71,
      "relation": "co-activation"
    }
  ]
}
```

여기서 `z0`, `z1`, `z2` 같은 차원은 처음부터 “용기”, “도덕성”, “공감성”으로 해석되지 않는다.  
그 의미는 많은 캐릭터가 같은 사건에서 어떤 행동을 했는지, 그리고 유저가 어떤 결과를 납득했는지를 학습한 뒤 사후적으로 분석해야 한다.

행동 결정도 다음처럼 바뀌어야 한다.

```text
기존 방식:
성격축 점수 → 규칙 기반 행동 선택

수정 방식:
latent persona vector × event/action embedding → 행동 점수
```

피드백은 단순 평가가 아니라 학습 신호가 된다.

```text
유저가 “완전 캐릭터다” 선택
→ 해당 행동 임베딩 방향으로 latent persona를 강화

유저가 “전혀 아님” 선택
→ 해당 행동 임베딩 방향에서 latent persona를 멀어지게 조정
```

실제 딥러닝 단계에서는 이 과정을 다음 학습 문제로 확장할 수 있다.

- 캐릭터 설명을 latent persona로 인코딩하는 encoder 학습
- 사건과 행동 후보를 embedding하는 event/action encoder 학습
- `latent persona · action embedding`으로 행동 확률을 예측하는 decision model 학습
- 유저 피드백을 보상 또는 선호 신호로 사용하는 preference learning
- 같은 사건에서 다른 캐릭터의 행동 차이를 학습하는 contrastive learning
- 행동 로그만 보고 캐릭터의 latent persona를 복원하는 inverse modeling

따라서 본 연구의 핵심 문장은 더 엄밀하게는 다음과 같다.

> 캐릭터를 사람이 정한 성격축에 배치하는 것이 아니라, 캐릭터 설명·사건·행동·결과·피드백의 대응 관계를 이용해 행동을 예측하는 잠재 페르소나 표현 공간을 학습한다.

### 4.3 세 가지 모델 구조

현재 연구 구조는 하나의 LLM 호출이나 하나의 규칙 엔진으로 설명하면 부족하다.  
최소한 다음 세 가지 모델을 구분해야 한다.

#### 모델 3: 잠재 페르소나 구조 설계 모델

이 모델이 연구 주제를 관통하는 핵심 모델이다.  
게임에서 수집된 데이터를 기반으로 학습된다.

```text
입력 데이터:
캐릭터 프롬프트
+ 성장 사건
+ 환경/부모 영향
+ 사건
+ 행동
+ 결과
+ 유저 피드백

출력:
행동을 예측하고 비교할 수 있는 latent persona structure 자체
+ 필요한 잠재 차원 수
+ 잠재 노드 간 연결 방식
+ 성장 사건과 행동 사건이 구조를 업데이트하는 방식
+ 프롬프트를 어떤 구조로 투영할지에 대한 설계
```

즉, 모델 3은 단순히 어떤 캐릭터 하나를 해석하거나, 이미 정해진 8차원 벡터 공간을 사용하는 모델이 아니다.  
모델 3은 많은 캐릭터와 사건 로그를 통해 **페르소나를 어떤 잠재 구조로 표현해야 행동을 잘 설명할 수 있는지 자체를 설계하는 딥러닝 모델**이다.

따라서 모델 3의 출력은 다음과 같은 형태가 되어야 한다.

```json
{
  "latent_schema_id": "LS_042",
  "latent_dimension": 32,
  "node_initialization_rule": "prompt-conditioned",
  "edge_update_rule": "development-and-feedback-conditioned",
  "latent_edges": [
    {
      "source": "z3",
      "target": "z17",
      "relation": "co-activation",
      "weight": 0.61
    }
  ],
  "update_functions": {
    "development_event": "f_dev(previous_latent, caregiver_signal, environment_event)",
    "world_event": "f_action(latent, event, action_result, feedback)"
  }
}
```

현재 프로토타입의 8차원은 고정 가정이 아니라, 화면에 보여주기 위한 임시 schema일 뿐이다.  
실제 연구에서는 모델 3이 데이터에 따라 8차원, 16차원, 32차원 또는 더 복잡한 그래프 구조를 선택할 수 있어야 한다.

#### 모델 1: 프롬프트 → 페르소나 해석 모델

모델 1은 유저가 입력한 자유 프롬프트를 모델 3이 학습한 잠재 구조 위에 배치한다.

```text
입력:
유저 자유 프롬프트

참조:
모델 3이 설계한 persona latent schema

출력:
아기 상태의 초기 latent persona seed
+ 프롬프트에서 강하게 작용한 근거 조각
+ 초기 잠재 연결 구조
```

중요한 점은 모델 1이 독립적으로 존재하면 안 된다는 것이다.  
모델 1은 모델 3이 설계한 구조 위에 프롬프트를 투영해야 한다.

#### 모델 2: 페르소나 → 사건/행동/서술 해석 모델

처음 표현으로는 “페르소나 → 프롬프트 해석 모델”이라고 할 수 있지만, 더 정확히는 다음에 가깝다.

```text
페르소나 구조 + 사건 구조
→ 성장 변화
→ 행동
→ 결과
→ 근거와 판단 서술
→ 변화된 페르소나 구조
```

모델 2는 잠재 페르소나 구조를 사건과 비교하여 어떤 행동이 나올지 생성한다.  
또한 유저가 이해할 수 있도록 프롬프트의 어떤 부분이 근거로 작용했는지 찾아 서술한다.

```text
입력:
latent persona
+ development event 또는 world event
+ event/action embedding

출력:
성장 변화 또는 행동
+ 변화 양상
+ 프롬프트 근거
+ 판단 서술
+ updated latent persona
```

### 4.4 현재 논리에서 보완해야 할 점

전체 방향은 타당하지만, 몇 가지를 더 명확히 해야 한다.

첫째, 모델 2의 이름은 조정하는 것이 좋다.  
“페르소나 → 프롬프트 해석”이라고 하면 이미 만들어진 페르소나를 다시 프롬프트로 번역하는 모델처럼 들릴 수 있다.  
실제로 필요한 것은 **페르소나-사건 상호작용 해석 모델** 또는 **페르소나 행동 생성 모델**에 가깝다.

둘째, 모델 3은 단순한 prior가 아니라 구조 생성 모델이므로, 처음부터 완성되어 있을 수 없다.  
초기에는 사람이 만든 약한 schema 또는 LLM/규칙 기반 schema generator로 시작하고, 데이터가 쌓이면 모델 3이 점차 구조 설계 능력을 학습해야 한다.

```text
초기 모델 3: 약한 schema generator 또는 LLM/규칙 기반 bootstrap
→ 모델 1로 캐릭터 생성
→ 모델 2로 시뮬레이션
→ 유저 피드백 수집
→ 모델 3이 latent schema / edge / update rule을 업데이트
→ 모델 1과 모델 2 개선
```

즉 모델 3은 처음부터 완성된 기반 모델이 아니라, 게임 데이터로 점점 강해지는 중심 모델이어야 한다.

셋째, latent 차원 수는 모델 3이 설계해야 한다.  
현재 프로토타입의 8차원은 시각화와 테스트를 위한 임시값이다.  
실제 연구에서는 다음을 실험해야 한다.

- 8차원, 16차원, 32차원, 64차원 등 차원 수 비교
- 차원 수에 따른 행동 예측 정확도
- 유저 납득도와 차원 수의 관계
- 너무 낮은 차원에서 캐릭터 차이가 뭉개지는지
- 너무 높은 차원에서 데이터가 부족해지는지

넷째, 모델 2는 행동만 만들면 부족하다.  
성장 변화와 행동을 만든 뒤 **그 결과가 다시 페르소나 구조를 어떻게 바꾸는지**까지 적용해야 한다.

```text
before_persona
→ event/action/result
→ after_persona
```

이 변화가 누적되어야 “페르소나가 발달한다”는 연구 주장이 성립한다.

다섯째, **모델 2의 품질은 모델 3의 품질에 의존한다.**

모델 2는 latent vector를 조건으로 삼아 행동과 서술을 생성하는 모델이다.  
따라서 모델 2를 fine-tuning할 때 다음 전제가 성립해야 한다.

- 모델 3이 설계한 latent 공간이 실제 행동 차이를 반영하고 있어야 한다.
- 모델 1이 프롬프트를 그 latent 공간 위에 의미 있게 투영하고 있어야 한다.

이 전제가 흔들리면 모델 2는 latent vector를 의미 있는 신호로 학습하지 못하고,  
단순히 사건 텍스트에 반응하는 일반 언어 모델과 다를 바 없어진다.

```text
M3가 latent 공간을 의미 있게 설계해야
  → M1이 프롬프트를 latent 공간에 의미 있게 배치하고
  → M2가 latent를 조건으로 삼아 행동과 서술을 학습할 수 있다
```

따라서 세 모델은 독립적으로 개선되지 않는다.  
M3의 latent 공간이 정교해질수록 M1과 M2도 함께 개선되는 구조이며,  
M2 fine-tuning의 효과는 M3의 성숙도에 비례한다.

프로토타입 단계에서 M2가 완전히 조건화되지 않을 수 있는 것은 이 때문이다.  
지금의 M2 fine-tuning은 최종 성능을 목표로 하는 것이 아니라,  
**latent → 행동 → 서술 → 피드백 루프가 작동하는 구조를 확인하는 것**을 목표로 한다.  
M3가 데이터와 함께 성장하면 M2도 자연스럽게 개선된다.

### 4.5 프로토타입 단계의 딥러닝 모델

프로토타입에서도 모델이 전혀 없는 규칙 엔진만으로는 연구 방향을 충분히 보여주기 어렵다.  
따라서 초기 구현에서는 두 층의 모델을 함께 사용한다.

첫째, 로컬 모델 서버는 `Transformers.js`의 `Xenova/all-MiniLM-L6-v2` feature-extraction 모델을 사용해 유저 프롬프트를 384차원 문장 임베딩으로 바꾼다.  
같은 프롬프트는 같은 문장 임베딩에서 출발하므로, 같은 입력이 매번 크게 다른 latent seed로 바뀌는 문제를 줄인다.

둘째, 브라우저 안에서는 이 문장 임베딩을 M3가 설계한 latent schema 차원으로 투영하고, 피드백 로그로 업데이트되는 작은 신경망을 사용한다.  
서버가 없을 때만 deterministic hash fallback을 사용한다.

현재 프로토타입의 딥러닝 구성은 다음과 같다.

```text
M3 schema generator
→ 이번 캐릭터에 사용할 latent schema 생성

M1 prompt encoder
→ all-MiniLM-L6-v2 prompt embedding을 latent seed로 투영
→ tanh-linear layer

M2 event/action encoder
→ 사건과 행동 embedding을 latent 공간으로 투영
→ tanh-linear layer

feedback trainer
→ 유저 피드백을 target signal로 바꿔 action encoder 가중치 업데이트
```

이 모델은 아직 연구용 최종 모델이 아니다.  
하지만 다음 조건을 만족한다.

- 실제 가중치를 가진다.
- 실제 pretrained text embedding model을 M1 입력으로 사용한다.
- 같은 프롬프트의 초기 해석이 결정적으로 유지된다.
- 피드백 로그로 loss를 계산한다.
- gradient update로 action encoder를 수정한다.
- 수정된 모델을 사용해 같은 사건을 재시뮬레이션할 수 있다.

즉 현재 프로토타입의 딥러닝 모델은 “최종 성능 모델”이 아니라, **게임 데이터가 모델 가중치를 바꾸고 그 변화가 행동 재시뮬레이션에 반영되는 루프**를 보여주기 위한 최소 학습 모델이다.

## 5. 왜 게임이 필요한가

본 연구에서 가장 중요한 문제는 데이터다.  
인터넷에는 특정 인물이나 캐릭터에 대한 설명문, 성격 정보, 대화 데이터는 존재할 수 있다.  
하지만 연구자가 원하는 형태의 데이터는 단순한 캐릭터 소개문이 아니다.

필요한 데이터는 다음과 같다.

```text
캐릭터 생성 프롬프트
+ 캐릭터 내부 성향 추정값
+ 상황
+ 캐릭터의 판단 과정
+ 선택 또는 행동
+ 결과
+ 엔딩
+ 유저의 납득 여부 / 재미 여부 / 재시도 여부
```

이런 형태의 데이터는 기존 웹 텍스트에서 그대로 얻기 어렵다.  
따라서 **게임을 통해 직접 수집하는 구조**가 필요하다.

게임은 단순한 부가 요소가 아니라,  
데이터 수집을 가능하게 만드는 핵심 장치다.

## 6. 게임의 기본 컨셉

### 6.1 초기 아이디어

처음 생각한 게임의 재미는 다음과 같다.

> “내가 만든 캐릭터가 성장했을 때 어떤 결과를 맞이하는지 빠르게 확인하는 재미”

이는 메이플스토리 같은 RPG에서 다양한 직업과 스킬을 체험하며  
“이 캐릭터는 어떻게 다르게 플레이될까?”를 탐구하는 재미와 닮아 있다.

다만 본 연구의 게임은 유저가 직접 모든 전투와 성장을 조작하지 않는다.  
대신 유저는 캐릭터를 만들고, 캐릭터는 자동으로 상황을 판단하며,  
유저는 그 결과를 관찰한다.

### 6.2 게임 루프

최종적으로 정리된 기본 루프는 다음과 같다.

```text
1. 유저가 캐릭터 생성
   - 자유 프롬프트 중심
   - 부모 / 양육자
   - 태어난 환경
   - 어린 시절 경험
   - 욕망
   - 두려움
   - 세계관 내 역할 등을 포함하면 좋지만 강제하지 않음

2. 시스템이 인물을 아기 상태의 초기 latent seed로 생성
   - 완성된 성격을 바로 부여하지 않음
   - 프롬프트는 초기 조건과 성장 환경을 제공함
   - 초기 latent는 아직 고정된 성격이 아니라 발달 가능성을 가진 씨앗에 가까움

3. 부모와 환경에 의한 성장 사건 발생
   - 양육 안정성
   - 결핍 또는 풍요
   - 첫 상실과 첫 인정
   - 세계가 요구한 역할
   - 이 과정에서 latent persona가 변화함
   - 변화 방향은 환경만으로 결정되지 않고 기존 latent seed와 상호작용함

4. 고정된 세계 안에서 성인기 사건 발생
   - 세계는 유저가 자유롭게 선택하지 않음
   - 사건은 연구자가 설계하거나 AI가 보조 생성

5. 캐릭터가 자동 판단
   - 유저가 직접 선택지를 고르는 것이 아니라
   - 캐릭터의 페르소나 구조에 따라 행동이 결정됨

6. 결과 출력
   - 사건 해결
   - 실패
   - 관계 변화
   - 성장
   - 타락
   - 죽음
   - 생존
   - 엔딩

7. 유저 피드백 수집
   - 결과가 캐릭터답다고 느꼈는가
   - 납득 가능한가
   - 재미있는가
   - 다시 해보고 싶은가
   - 다른 캐릭터로 실험하고 싶은가
```

### 6.3 생성된 인물은 반드시 아기부터 시작한다

중요한 설계 수정점은 “완성된 캐릭터”를 바로 사건에 투입하지 않는다는 것이다.  
유저가 프롬프트에 “겁이 많지만 친구를 버리지 못하는 기사”라고 적더라도, 시스템은 그 문장을 성인 캐릭터의 고정 성격표로 해석하지 않는다.

대신 다음 흐름으로 처리한다.

```text
자유 프롬프트
→ 아기 상태의 초기 latent seed 생성
→ 부모 / 양육 / 환경 / 어린 시절 사건
→ latent persona 변화
→ 성인기 사건 투입
→ 행동과 결과 수집
```

이때 부모와 환경은 단순 배경 설명이 아니라 페르소나를 변화시키는 원인으로 기록되어야 한다.

예를 들어:

```json
{
  "development_event_id": "G001",
  "phase": "infancy",
  "event": "첫 양육자의 손",
  "environment_signal": "엄격한 아버지와 따뜻한 어머니",
  "latent_before": [0.12, -0.31, 0.44],
  "adaptation": "복종하면 안전하다는 규칙을 배운다",
  "latent_after": [0.08, -0.12, 0.57]
}
```

핵심은 같은 환경도 모든 인물에게 같은 변화를 만들지 않는다는 점이다.  
기존 latent seed가 다르면 같은 엄격한 부모 밑에서도 어떤 인물은 권위 순응 쪽으로, 어떤 인물은 반항 쪽으로, 어떤 인물은 인정 욕구 쪽으로 변화할 수 있다.

따라서 성장 모델은 다음 형태가 되어야 한다.

```text
next_latent = f(previous_latent, environment_event, caregiver_signal, feedback)
```

이 구조를 넣어야 “페르소나는 고정 입력값이 아니라 발달 과정과 행동 결과 속에서 형성되는 표현”이라는 연구 방향이 더 분명해진다.

## 7. 중요한 설계 결정: 유저는 세계를 고르지 않는다

### 7.1 이유

세계까지 유저가 자유롭게 만들면 문제가 생긴다.

```text
캐릭터도 자유
세계도 자유
사건도 자유
결과도 자유
```

이렇게 되면 데이터가 너무 흩어진다.  
무엇이 캐릭터 차이 때문이고, 무엇이 세계 차이 때문인지 분석하기 어렵다.

따라서 연구 목적상 세계는 고정하는 것이 낫다.

```text
세계 = 고정
사건 구조 = 반고정
캐릭터 = 자유
행동 결과 = 비교 대상
```

이렇게 해야 같은 세계와 같은 사건 속에서  
서로 다른 캐릭터들이 어떻게 다르게 판단하는지 비교할 수 있다.

### 7.2 데이터 관점에서의 장점

세계가 고정되면 다음 비교가 가능해진다.

```text
같은 사건 A
- 캐릭터 1은 도망감
- 캐릭터 2는 협상함
- 캐릭터 3은 배신함
- 캐릭터 4는 희생함
```

이때 행동 차이는 세계 차이가 아니라 캐릭터 차이에서 나온 것으로 볼 수 있다.  
따라서 페르소나 구조 학습에 더 유리하다.

## 8. 사건은 사람이 만들 것인가, AI가 만들 것인가

### 8.1 완전 수동 제작의 장점과 한계

사람이 사건을 직접 만들면 품질이 안정적이다.  
하지만 사건 수가 제한되고, 콘텐츠 확장이 어렵다.

장점:

- 세계관 일관성 유지
- 연구자가 의도한 변수를 통제 가능
- 특정 성격 축을 자극하는 사건 설계 가능

한계:

- 제작 비용이 큼
- 반복 플레이 시 금방 익숙해짐
- 데이터 다양성 확보가 어려움

### 8.2 완전 AI 생성의 장점과 한계

AI가 사건을 생성하면 다양성은 커진다.  
하지만 사건 품질과 실험 통제가 약해질 수 있다.

장점:

- 사건 수를 빠르게 늘릴 수 있음
- 유저별로 새로운 경험 제공 가능
- 반복 플레이 유도 가능

한계:

- 사건 난이도와 구조가 흔들릴 수 있음
- 비교 가능한 데이터가 줄어들 수 있음
- 캐릭터 행동 차이와 사건 차이가 섞일 수 있음

### 8.3 권장 방식: 고정 세계 + 템플릿 사건 + AI 변주

가장 적절한 방식은 절충안이다.

```text
세계관: 연구자가 고정
핵심 사건 구조: 연구자가 설계
세부 묘사와 변주: AI가 생성
결과 판정: 규칙 + LLM 혼합
```

예를 들어 사건 템플릿은 다음처럼 만든다.

```json
{
  "event_id": "E001",
  "event_type": "moral_dilemma",
  "core_conflict": "한 명을 희생하면 다수를 구할 수 있다",
  "triggered_traits": ["도덕성", "공리주의", "애착", "위험감수성"],
  "fixed_variables": {
    "risk_level": "high",
    "time_pressure": "high",
    "social_pressure": "medium"
  },
  "ai_generated_surface": {
    "location": "폐허가 된 성문 앞",
    "npc": "부상당한 동료",
    "object": "무너지는 다리"
  }
}
```

이렇게 하면 연구적으로는 같은 사건 구조를 유지하면서도,  
유저에게는 다양한 이야기처럼 느끼게 할 수 있다.

## 9. 유저가 선택지를 고르면 안 되는가?

이 게임의 핵심은 유저가 선택하는 게임이 아니라,  
**유저가 만든 캐릭터가 스스로 판단하는 것을 관찰하는 게임**이다.

따라서 일반적인 선택지 게임처럼 만들면 연구 목적이 흐려질 수 있다.

```text
일반 선택지 게임:
유저의 선택 데이터가 쌓임

본 연구의 게임:
캐릭터의 자동 판단 데이터가 쌓임
```

다만 유저의 개입을 완전히 없애면 지루해질 수 있다.  
그래서 유저는 선택자가 아니라 **관찰자이자 창조자**가 되어야 한다.

유저가 할 수 있는 개입은 다음 정도가 적절하다.

- 캐릭터 생성
- 캐릭터 설명 수정
- 같은 세계에 다른 캐릭터 투입
- 결과 비교
- “이 결과가 캐릭터답다 / 아니다” 피드백
- “이 캐릭터라면 다르게 했을 것 같다” 짧은 수정 입력
- 엔딩 공유
- 캐릭터 복제 후 일부 성격만 바꾸어 재실험

## 10. 루즈함 문제에 대한 대응

### 10.1 선택 이유 서술은 필수로 만들면 안 된다

처음에는 선택 이유 서술이나 캐릭터 질문 응답을 통해 데이터를 모으는 방식을 생각했다.  
하지만 이 방식은 너무 루즈해질 위험이 있다.

유저는 게임을 하러 왔는데,  
계속 설문지나 자기소개서를 작성해야 한다고 느낄 수 있다.

따라서 긴 서술형 입력은 선택 사항이어야 한다.

### 10.2 데이터 수집은 플레이 속에 숨어 있어야 한다

핵심은 유저가 “데이터를 제공한다”고 느끼지 않게 만드는 것이다.

좋은 방식:

```text
캐릭터 생성 프롬프트
→ 자동 시뮬레이션
→ 짧은 결과
→ 한 줄 피드백
→ 다른 캐릭터로 재시도
```

나쁜 방식:

```text
캐릭터 생성
→ 성격 질문 20개
→ 선택 이유 서술
→ 추가 질문 10개
→ 긴 설문
```

### 10.3 피드백은 가볍게 만든다

피드백은 다음처럼 짧아야 한다.

```text
이 결과가 캐릭터답나요?

[완전 캐릭터다]
[조금 애매함]
[전혀 아님]
```

또는:

```text
이 캐릭터라면 실제로 어떻게 했을까요?

[비슷하게 했을 듯]
[더 공격적으로 행동했을 듯]
[더 조심했을 듯]
[동료를 먼저 챙겼을 듯]
[직접 입력]
```

직접 입력은 열어두되, 강제하지 않는다.

## 11. 재미의 핵심 구조

이 게임의 재미는 조작의 재미가 아니라,  
**캐릭터 실험의 재미**다.

### 11.1 빠른 결과 확인

유저는 긴 육성 과정을 거치지 않고도  
자신이 만든 캐릭터의 삶과 엔딩을 빠르게 볼 수 있다.

```text
“이런 성격의 캐릭터는 이 세계에서 살아남을까?”
“정의로운 캐릭터와 이기적인 캐릭터는 같은 사건에서 어떻게 달라질까?”
“약점 하나만 바꾸면 엔딩이 달라질까?”
```

### 11.2 비교의 재미

가장 중요한 재미는 비교다.

```text
캐릭터 A: 용감하지만 충동적 → 동료를 구하다 사망
캐릭터 B: 냉정하고 계산적 → 동료를 버리고 생존
캐릭터 C: 겁이 많지만 공감성이 높음 → 도망치다 돌아와 희생
```

유저는 “내가 만든 캐릭터가 어떤 인간인가”를 결과를 통해 확인한다.

### 11.3 엔딩 수집의 재미

엔딩은 재방문을 유도하는 핵심 장치가 될 수 있다.

예시 엔딩:

- 생존자
- 배신자
- 순교자
- 권력자
- 도망자
- 구원자
- 괴물
- 실패한 영웅
- 아무도 기억하지 않는 자
- 세계를 바꾼 자

엔딩을 수집하게 만들면 유저는 자연스럽게 다양한 캐릭터를 만들게 된다.  
이는 곧 데이터 다양성으로 이어진다.

## 13. 연구적으로 중요한 데이터 포인트

가장 중요한 것은 단순히 “유저가 어떤 캐릭터를 만들었는가”가 아니다.  
핵심은 다음의 대응 관계다.

```text
캐릭터 설명
→ 시스템이 추정한 페르소나 구조
→ 사건
→ 행동
→ 결과
→ 유저의 납득 여부
```

이 대응 관계가 쌓이면 다음 연구가 가능해진다.

- 프롬프트 기반 캐릭터 설명을 행동 기반 페르소나 벡터로 변환
- 같은 사건에서 캐릭터별 행동 차이 분석
- 성격 축 간 연결 구조 추정
- 유저가 납득하는 캐릭터 행동 패턴 학습
- LLM 페르소나의 일관성 평가
- 캐릭터 자동 생성 모델 학습
- 인간 행동 시뮬레이션용 개체형 에이전트 구축

### 후보 1

### 후보 2

### 후보 3

## 15. 연구 목적 문장 초안

본 연구의 목적은 유저가 생성한 캐릭터가 고정된 세계관과 사건 구조 안에서 자동으로 판단하고 행동하는 게임형 시뮬레이션 환경을 구축하고, 이 과정에서 수집되는 캐릭터 설명, 상황, 행동, 결과, 유저 피드백 데이터를 활용하여 LLM 기반 페르소나의 표현 공간을 학습하는 것이다. 기존 페르소나 에이전트 연구가 주로 사람이 사전에 정의한 성격·배경·말투 프롬프트에 의존했다면, 본 연구는 캐릭터가 실제 상황 속에서 어떤 판단을 반복하는지를 중심으로 페르소나를 모델링한다. 이를 통해 개별 페르소나를 단순한 문장형 설정이 아니라, 성격 축과 가치, 동기, 행동 경향이 상호작용하는 네트워크형 구조로 표현하고자 한다.

연구 목적상 세계관은 너무 자유롭지 않아야 한다.

- 생존, 도덕, 권력, 관계, 희생, 배신이 모두 발생 가능해야 함
- 사건 구조를 반복적으로 만들기 쉬워야 함
- 캐릭터 다양성이 잘 드러나야 함
- 엔딩이 직관적으로 재미있어야 함

예시:

```text
몰락 직전의 왕국
- 전쟁과 기근이 지속됨
- 귀족, 기사, 마법사, 평민, 반란군이 존재
- 왕국을 구할 수도, 배신할 수도, 도망칠 수도 있음
- 생존, 명예, 사랑, 권력, 복수, 희생이 모두 가능
```

## 19. 이 연구의 차별점

이 연구는 단순한 캐릭터 챗봇 제작이 아니다.

기존 방식:

```text
캐릭터 설정을 잘 써서 LLM이 그럴듯하게 말하게 함
```

본 연구:

```text
캐릭터가 상황 속에서 반복적으로 어떤 판단을 하는지 수집하고,
그 행동 결과를 통해 페르소나 구조를 학습함
```

차별점은 다음과 같다.

- 프롬프트 중심 페르소나가 아니라 행동 중심 페르소나
- 단일 성격 설명이 아니라 성격 축 간 연결 구조
- 대화 응답 평가가 아니라 상황 판단과 결과 평가
- 단순 캐릭터 롤플레잉이 아니라 개체형 AI 시뮬레이션으로 확장 가능
- 게임을 데이터 수집 장치로 활용
- 유저가 만든 다양한 캐릭터를 통해 페르소나 공간을 확장

## 20. 참고할 수 있는 외부 흐름

최근 LLM 기반 역할 수행 에이전트 연구는 fictional character, celebrity, historical figure 등 이미 존재하는 역할을 얼마나 잘 모사하는지에 관심을 두는 경우가 많다. 또한 CharacterGPT와 같은 연구는 소설 요약에서 personality, physical description, motivations, backstory, emotions, relationships, growth 등의 특성을 추출해 캐릭터 페르소나를 재구성하는 방향을 제안한다. 본 연구는 이러한 정적·설명형 페르소나 구성에서 한 걸음 더 나아가, 유저가 만든 캐릭터가 사건 속에서 보이는 행동 결과를 데이터로 삼는다는 점에서 차별화된다.

게임 설계 측면에서는 자기결정성이론 기반의 게이미피케이션 연구를 참고할 수 있다. 단순히 배지나 점수를 붙이는 것만으로 동기가 생기는 것이 아니라, 유저가 의미 있는 선택감, 유능감, 피드백을 느껴야 지속적인 참여가 가능하다. 따라서 본 게임은 긴 설문보다 빠른 결과, 캐릭터 비교, 엔딩 수집, 재시도 욕구를 중심으로 설계하는 것이 적절하다.

AI 스토리텔링 게임 흐름도 참고할 수 있다. AI Dungeon처럼 자유도가 높은 텍스트 어드벤처는 강한 몰입을 만들 수 있지만, 연구 데이터 관점에서는 통제가 어렵다. 반대로 Hidden Door와 같은 구조화된 AI 스토리텔링 게임은 유저의 자유를 완전히 막지 않으면서도 세계와 사건에 경계를 두어 서사 일관성을 유지한다. 본 연구 역시 자유 세계 생성보다는 고정 세계관과 사건 템플릿을 유지하고, AI는 세부 묘사와 변주를 담당하게 하는 방식이 적절하다.

## 22. 현재까지의 핵심 결론

현재까지의 결론은 다음 한 문장으로 정리할 수 있다.

> 본 연구는 유저가 생성한 캐릭터를 고정된 세계관의 사건에 투입하고, 캐릭터가 자동으로 판단한 행동과 그 결과를 수집함으로써, 기존의 사전 정의형 프롬프트 페르소나를 넘어 행동 기반의 페르소나 표현 공간을 학습하려는 연구이다.

더 짧게 말하면:

> **캐릭터를 만들고, 사건에 던지고, 행동 결과를 수집해서, 페르소나를 학습한다.**
